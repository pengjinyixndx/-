# 心跳副本 · HEARTBEAT DUO

微信小程序《心跳副本》的**逆向分析**与**静态网页复刻版**。

> 一个为情侣做的真心话大冒险小游戏。原版是微信小程序，本项目先把它的
> 打包文件、缓存与运行时内存翻了一遍，再照着重写了一个纯前端的网页版。

**打开方式**：直接双击 `index.html`。零依赖、无构建、不发任何网络请求，
所有数据只写在你自己的 `localStorage` 里。

   ├─ unpack_wxapkg.py           ← wxapkg 解包器

   ├─ bank-audit.mjs             ← 题库审计
   └─ dom-smoke.mjs              ← DOM 集成测试

## 逆向结论摘要

静态三条路全被堵死：`__APP__.wxapkg`（熵 7.58）、`applet.db`、MMKV 存储
**全部加密**，网上通用的「V1MM + XOR 0x66」解包法在这台机器上已失效。

于是转向**运行时**：小程序在跑，解密后的 JS 必然在宿主进程内存里。
`OpenProcess` + `VirtualQueryEx` + `ReadProcessMemory` 枚举可读区，
再用 UTF-8 / UTF-16LE / GBK 三种编码做锚点探针——命中。

从 pid 120748（`WeChatAppEx`，583 MB）恢复出了**原版的完整「玩法说明」页面**：

> 心跳副本是一款专为情侣设计的互动游戏合集，包含真心话大冒险、骰子、大转盘、红绿灯等多种游戏。
>
> 使用步骤：1 角色名称中设置双方的昵称 · 2 选择想要玩的游戏和难度等级 · 3 按照游戏提示进行互动
>
> **会员权益**：开通会员后可解锁所有游戏和高级难度，获得更丰富的游戏内容体验。

三个结论：五个模块与复刻版**完全一致**；引导流程得到确认；
**原版是付费会员解锁所有游戏与高级难度**。复刻版**不做任何解锁门槛** ——
七档全部开放，唯一的前置是 18+ 档的成年确认。

题库正文未能命中——13 万条文本片段里以全角问号结尾的只有 3 条广告语，
应该是切后台后深层数据被回收了。

完整过程、失败尝试与证据见 **[analysis/心跳副本-逆向分析.md](analysis/心跳副本-逆向分析.md)**。

## 复刻版功能

| 模块 | 说明 |
|---|---|
| 角色名称 | 自动分词，名字轮转决定「轮到谁」 |
| 真心话大冒险 | 7 档强度，每档 100 张，同档洗牌 |
| 大转盘 | Canvas 12 扇区，物理摩擦减速 + 指针判定 |
| 骰子 | 真 3D 立方体（CSS `preserve-3d`），旋转落定到目标面 |
| 红绿灯 | 抢跑判定 + 反应时测量，0.62s / 0.33s 两档窗口 |
| 自定义题库 | 按 强度 × 类型 存放，支持一次贴多行 |
| 玩法说明 | 7 段规则 |

增补：EKG 心电背景（振幅随抽卡起伏）、WebAudio 合成心跳音效、
粒子爆发、红绿灯战绩持久化、18+ 档年龄确认弹窗。

### 七档强度按「动作机制」递进

| 档位 | 动作机制 | 尺度 |
|---|---|---|
| 温和 | 说话、表演、猜测 | 零身体接触 |
| 热辣 | 耳语、对视、轻触 | 只到牵手 / 拥抱 / 额头 / 手背 |
| 猛烈 | 拉、抱、按、压、跨坐 | 大幅度肢体动作，衣物开始离开 |
| **灼热** | 收紧、锁住、夹住、悬空、压制 | 力度与贴身摩擦拉满，**仍不碰敏感部位** |
| **临界** | 隔衣按压 / 托贴 / 推移 / 指尖 / 腿 / 身体 | **隔着衣物**接触胸、大腿内侧、臀，**还不脱** |
| 极限 | 髋部、手腕压制、解开全部衣物、直接触碰 | 衣物离开，全身接触 |
| 禁区 | 进入、体位、用嘴、用手 | **18+**，敏感部位用「小花园」等代称 |

尺度是按**机械动作的强度**定义的，不是按形容词的强度。
档位边界由 `analysis/tier-boundary.mjs` 强制校验：
敏感部位首见于「临界」、直接触碰首见于「极限」、性行为首见于「禁区」。

## 验证

三套工具，都可直接跑：

```bash
node analysis/tier-boundary.mjs .  # 档位边界（敏感部位/脱衣/性行为 出现在哪一档）
node analysis/bank-audit.mjs .     # 题库审计
node analysis/dom-smoke.mjs .      # DOM 集成测试（全量，含遍历 700 张牌，需几分钟）

SKIP_SLOW=1 node analysis/dom-smoke.mjs .   # 日常回归：跳过两条遍历用例
```

`tier-boundary.mjs` 把「哪个档位才允许出现什么」写成可执行规则：
**敏感部位**最早只许出现在「临界」，**脱衣/直接接触**最早只许出现在「极限」，
**性行为**最早只许出现在「禁区」。700 条靠人眼守不住，所以交给脚本。

`bank-audit.mjs` 用 `vm` 真实加载题库，检查：数量、精确重复、规范化重复、
**字符二元组 Jaccard 相似度 ≥ 42% 的高相似对**、**禁用机制**、
以及**机制单一度**（任一具名机制占比 > 40% 即报错）。

`dom-smoke.mjs` 是一个自建迷你 DOM（元素树、选择器引擎、`innerHTML` 解析、
事件冒泡、`classList`、可控的 `setTimeout` / `requestAnimationFrame` 队列），
在其中执行**真实的 `app.js`** 并驱动交互。

当前状态：

```
700 条题目全部落在各自档位的边界内
合计 700 条题目，0 个问题
24/24 passed, 0 runtime error(s)
```

### 这些工具抓到的真问题（不是形式主义）

1. 温和档 20 条大冒险里有 **9 条以「说 / 讲 / 叫」开头**；
2. 猛烈与极限的真心话有 **14 条完全重复**（扩建时复制了旧内容）；
3. 极限档 **24/50 条以「嘴唇 / 舌尖」起手** —— 每一行文字都不重复，
   去重全绿，但读起来是同一套动作。这正是用户投诉的
   「中间三档本质一致，一直停留在表层的轻轻触碰」。修完降到 5/50。
4. 新增的「临界」档一度 **33/50 都是「按 / 压」** —— 同样是单一机制刷屏，
   换掉动词后分布变成 13/9/8/8/6/5。
5. **18+ 档打不开**：既被积分门槛卡死，又依赖 `window.confirm`
   —— 原生弹窗在内嵌 WebView 里不可靠，返回 false 时点击毫无反应。
   改为自绘确认弹窗后修复，并补了回归测试。
   （「心跳值」积分解锁后来按需求**整个移除**，七档全开。）
6. **旧存档污染新状态**：`load()` 原本 `Object.assign` 整个存档，
   于是已经删掉的 `points` / `unlocked` 会一直留在状态和 localStorage 里。
   改成按 schema 白名单过滤后解决，并加了断言。
7. 属性选择器 token 化错误导致点击委托静默失效、`textContent` 语义错误
   导致渲染内容丢失。

第 3 与第 5 条直接催生了「机制单一度」和「档位边界」这两条规则。
